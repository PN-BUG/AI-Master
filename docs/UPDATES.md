# AIMaster 更新约定

## 用户安装与更新

安装位置以当前进程的 `Environment.ProcessPath` 为准，取该 EXE 的父目录。更新不读取快捷方式，不依赖当前工作目录，也不迁移或重命名安装目录。未设置任务栏快捷方式的用户使用相同流程。

1. 检查 GitHub Release，锁定具体版本标签，选择当前进程架构和发布类型对应的 ZIP。轻量版通过安装目录中的 `AIMaster.runtimeconfig.json` 识别，不再按 EXE 大小猜测。
2. 在系统临时目录下载，限制下载与解压大小；核对 SHA-256、程序版本和发布类型。API 未提供摘要时，读取同一版本 ZIP 的 `.sha256` 附件。缺少校验信息则停止自动安装，保留原程序。
3. 拒绝 ZIP 路径穿越、数据流、链接和歧义路径。包中的设置文件与更新器保留路径不能覆盖用户数据；安装目录中的链接和目录冲突也会阻止更新。
4. 独立更新器取得安装目录的独占锁，完成临时文件准备，再写入准备完成标记。主程序看到标记后才退出；准备失败时继续运行原版本。更新器使用 PID、进程启动时间和 EXE 路径核对进程身份。
5. 等待原进程退出。将待安装文件暂存到安装目录内的 `.aimaster-update`，在每次替换前持久化回滚清单。同一磁盘上的 `File.Replace` 替换已有文件并保存备份；新增文件用 `File.Move` 安装。

   更新期间普通启动会检查更新锁并提示等待，避免在多文件替换途中启动。更新器负责的重启带有内部启动标记。
6. 从原 EXE 路径重启，工作目录也设为原安装目录。如果新进程在三秒内退出，则恢复旧文件。全部步骤成功后记录提交状态，清理临时文件与备份。
7. 覆盖失败时按清单逆序恢复，撤回新增文件。失败日志存入 `%LOCALAPPDATA%\AIMaster\UpdateLogs`；恢复失败时保留备份和事务清单。下一次更新会在程序退出后先恢复尚未提交的事务。

只覆盖更新包包含的文件，不清空安装目录。用户设置位于 `%LOCALAPPDATA%\AIMaster\settings.json`，不参与程序文件替换。不可写的安装目录会在退出前报告错误；不会自行换目录安装，也不会自动提权后启动高权限程序。

## 本地构建与当前运行副本

`build.ps1` / `package-all.cmd` 生成发布目录和 ZIP，供上传或分发。构建产物不等于正在运行的用户安装。目标发布目录被进程占用时，打包脚本明确停止，而不是另建版本目录冒充安装成功。

更新本机当前运行副本：

```powershell
.\update-running.ps1
# 多个 AIMaster 进程时明确选择：
.\update-running.ps1 -ApplicationProcessId 12345
```

该命令读取选定进程的真实 EXE 路径和 PE 架构，在临时目录构建并验证版本，然后调用与应用内更新相同的文件事务引擎，停止选定进程、覆盖原目录、重启并核对 EXE 摘要。它不读取或改写快捷方式，也不更新其他副本。

发布新版本必须递增项目版本，并上传各架构/发布类型的 ZIP 及其 `.zip.sha256` 附件。只修改源码，或仅在本地生成新的目录，都不会向其他用户交付更新。

## 验证范围

```powershell
dotnet run --project .\tests\AIMaster.Smoke\AIMaster.Smoke.csproj -c Release
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\UpdateTransaction.Tests.ps1
```

测试覆盖路径与校验、生成的嵌入脚本、原目录覆盖、设置保留、文件锁导致的部分失败、新增文件撤回、启动退出、恢复失败备份保留，以及中断事务恢复。

SHA-256 用于校验文件完整性，信任来源仍是 HTTPS GitHub Release；当前没有独立的发布签名体系。三秒启动检测仅确认进程未立即退出，不能替代应用功能或服务器连接验证。多文件更新通过逐文件替换和持久化清单实现恢复，不宣称整个目录替换具有跨文件原子性，也不保证断电后的磁盘持久化。
